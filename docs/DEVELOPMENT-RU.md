# Battery Monitor 0.12.0 — Design Update

Актуальная версия: 0.12.0. Обновлены боковая панель, карточки заряда, светлая и тёмная темы, раздел совместимости и подпись автора. Протокол обновлений и режимы виджета сохранены.

## Публикация версии 0.12.0

1. В локальной папке проекта восстановите конфигурацию обновлений с прежним ключом через `configure-updates.cmd`, указав `kross873/battery-monitor-releases`. Если ранее выпущенный ключ отсутствует, восстановите его из резервной копии, а не создавайте новый.
2. Запустите `test-updates.cmd`, затем `make-release.cmd`. Проверьте установщик на Windows и наличие лицензий.
3. Убедитесь, что папка `release` содержит `BatteryMonitor-0.12.0-Setup.exe` и `update.json`. Если изменились только `RELEASE-NOTES.txt`, повторно запустите `sign-release.cmd` для уже проверенного установщика.
4. Опубликуйте соответствующие исходники с тегом `v0.12.0` в [BatteryMonitor](https://github.com/kross873/BatteryMonitor), включая необходимые сборочные файлы и уведомления о лицензиях. Публичный шаблон конфигурации остаётся пустым; для воспроизведения официальной конфигурации можно предоставить имя репозитория и открытый ключ, но никогда закрытый ключ.
5. В [battery-monitor-releases](https://github.com/kross873/battery-monitor-releases) создайте релиз с тегом `v0.12.0`, загрузите оба файла, добавьте ссылку на соответствующие исходники и назначьте релиз latest только после проверки.
6. Проверьте обнаружение и установку обновления из предыдущей настроенной версии; после установки 0.12.0 проверка должна сообщить, что установлена актуальная версия.

Подпись манифеста не является Authenticode-подписью установщика. Не отключайте защиту Windows.

## Общие инструкции и история предыдущих версий

Ниже сохранены инструкции для 0.11.0 и более ранних выпусков. Имена файлов и теги в исторических примерах относятся к указанным версиям; для текущего релиза используйте шаги выше.

Один установщик, два взаимоисключающих режима отображения. Основа приложения — проверенная пользователем 0.10.3. Мод Windhawk 0.4.0 сохранён без изменений.

## Установка
1. Закройте Battery Monitor через меню «Выход». Сохраните старую сборку для отката.
2. Запустите build-setup.cmd (.NET 8 SDK и Inno Setup 6.3+ / 7 нужны только на компьютере сборки).
3. Запустите release\BatteryMonitor-0.11.0-Setup.exe. Выберите «Без Windhawk» (по умолчанию) или «С Windhawk». Повторная установка позволяет поменять режим, ранее выбранный режим подставляется автоматически. Выберите автозапуск в мастере.
4. Без Windhawk: отключите старый мод Battery Monitor, если он есть. Отдельный виджет 0.10.3 работает как прежде, доступен запасной режим обычных значков. Сторонний мод не нужен.
5. С Windhawk: отдельное окно не создаётся. Программа публикует заряд выбранных устройств в локальный реестр для мода 0.4.0. Если мод уже установлен, включите его. Иначе следуйте инструкции, которую можно открыть в конце установки или из меню Пуск. Windhawk и локальный мод устанавливаются/компилируются отдельно. Установщик не загружает Windhawk и не изменяет его настройки.
6. Оба режима используют общие настройки оформления, выбора устройств, частоты и автозапуска. Установка сбрасывает только запасной режим обычных значков и устаревшие показания. При выходе приложения показания для мода очищаются. Если старый мод включён в режиме без Windhawk, свежих данных он не получит.

## Смена режима и удаление
Закройте приложение и снова запустите тот же установщик. При выборе самостоятельного режима отключите старый мод. Удаление приложения очищает автозапуск и данные заряда, но не удаляет Windhawk и его мод; отключите или удалите мод самостоятельно. Настройки внешнего вида сохраняются для обновления. Для отката закройте приложение, установите 0.10.3 и отключите мод.

## Переносимая сборка
build-windows.cmd создаёт publish. Переносите всю папку. Режим определяется существующей настройкой HKCU; на чистом ПК по умолчанию самостоятельный. Для переключения предпочтителен установщик.

## Поддержка устройств
- AJAZZ AJ179 APEX (3151:5007 FFFF:0002), ранее проверена пользователем.
- Стандартное поле заряда HID, стандартный Bluetooth Battery Level и контроллеры Windows — только когда устройство предоставляет данные; совместимость с каждой моделью не гарантирована.
- Фирменные протоколы USB Logitech, Razer, SteelSeries, Corsair, HyperX и др. не реализованы. Обнаружение не означает, что можно считать заряд.
- G435 через USB-приёмник: точный автоматический заряд недоступен, ручная отметка по светодиоду сохранена. Программа не выдумывает проценты.

## Проверка
На Windows проверьте оба варианта установки, перезагрузку, Win, автоскрытие, обновление заряда, скрытие виджета в настройках и отсутствие дублирования. Для переключения режима повторите установку. Без Windhawk отдельное окно не резервирует место в панели задач; в режиме Windhawk совместимость зависит от версии Windows и мода. В этой среде нет .NET SDK, Inno Setup и Windows; проверены исходники и состав архива, но EXE не скомпилирован и не протестирован. Установщик не подписан; не отключайте антивирус и проверьте сборку перед распространением.

## 0.11.0 — Центр обновлений

В настройках есть третья вкладка «Обновления». Показ текущей версии, проверка подписанного манифеста, загрузка с прогрессом, проверка размера и SHA-256, подтверждение установки. Проверка при запуске выключена по умолчанию; её можно включить на вкладке (настройка сохраняется сразу). Ничего не устанавливается автоматически. Установка запускает обычный интерактивный мастер после выхода приложения; прежний режим и автозапуск подставляются, режим обычных значков не сбрасывается при сохранении прежнего режима. Выбранные устройства, язык и оформление хранятся в прежних ключах реестра.

### Быстро попробовать без GitHub

`build-setup.cmd` создаёт обычный установщик. Вкладка есть, но проверка отключена, пока издатель не настроит источник. Для реальных обновлений нужно подготовить источник **до** сборки и раздачи 0.11.0. Версии, ранее установленные без настроенного источника, нужно один раз обновить вручную.

### Настройка для издателя (один раз)

1. Создайте на GitHub публичный репозиторий, например `battery-monitor-releases`. В этом отдельном репозитории будут публичные релизы с установщиками и манифестами; соответствующие исходники публикуются в основном репозитории. Не добавляйте туда личные данные. Никакие репозитории этим архивом автоматически не создаются.
2. На компьютере сборки запустите `configure-updates.cmd`, введите точное `владелец/репозиторий` (латиницей, без URL), подтвердите создание ключа командой YES, если это первый выпуск. Скрипт создаёт ключ RSA-3072 в `%LOCALAPPDATA%\BatteryMonitorPublisher` и записывает только открытый ключ и имя репозитория в `update-config.json`. Сделайте защищённую резервную копию закрытого PEM-файла. Никому его не отправляйте, не загружайте на GitHub и не включайте в архивы. Закрытый ключ используется для подписи релизов и нужен только издателю. Если потерять ключ, существующим клиентам потребуется вручную установить новый доверенный ключ.
3. Запустите `test-updates.cmd` для локальных тестов протокола (тесты не требуют сети и используют временные тестовые ключи в памяти).
4. Запустите `make-release.cmd` (или `build-setup.cmd`, затем `sign-release.cmd`). Это соберёт установщик и создаст `release\update.json` с подписанными данными для этого файла. Убедитесь, что Windows и антивирус проверили установщик; не распространяйте непроверенную сборку.
5. В GitHub откройте Releases → Draft a new release. Тег строго `v0.11.0`, название произвольное. Вложите `BatteryMonitor-0.11.0-Setup.exe` и `update.json` из `release`. Опубликуйте как обычный релиз (не prerelease) и назначьте latest. Пользователям 0.10.8 один раз передайте этот настроенный Setup.exe в ZIP-архиве. Сам `update.json` и закрытый ключ им не нужны.
6. После установки 0.11.0 проверка должна показать «Установлена актуальная версия». Реальный тест обновления потребует более новой версии и её подписанного релиза, например v0.11.1.

### Каждый следующий выпуск

Сохраните **тот же** `update-config.json` из настроенного проекта или восстановите его через `configure-updates.cmd` с тем же репозиторием и ключом. Повышайте версию в `.csproj`, `.iss`, скриптах сборки и строках приложения. После сборки запустите `make-release.cmd` или подпишите уже проверенный свежий Setup.exe через `sign-release.cmd`. В новый релиз GitHub с тегом `vX.Y.Z` загрузите соответствующий установщик и новый `update.json`. Для автоматического обнаружения назначьте его latest. Не заменяйте файл после подписания: подпись включает его SHA-256 и размер. Не публикуйте закрытый ключ, исходный сборочный архив или файлы диагностики. Не подписывайте чужие или непроверенные файлы.

### Безопасность и ограничения

Клиент обращается только по HTTPS к GitHub и его CDN, читает `releases/latest/download/update.json`, проверяет подпись RSA/SHA-256 открытым ключом, встроенным в приложение, проверяет числовую версию и скачивает соответствующий файл по тегу. Ограничены размер манифеста и установщика, число перенаправлений и время запроса. Повторно сверяет SHA-256 непосредственно перед запуском. Более старые или равные версии не устанавливаются. Неверный манифест, подпись, размер или хеш останавливают процесс. Подпись манифеста — **не** Authenticode-подпись Windows: установщик остаётся неподписанным с точки зрения Windows, и защиту Windows/антивирус не следует отключать. Не публикуйте экспериментальные релизы как latest до проверки. Установщик остаётся в локальном каталоге BatteryMonitor\Updates после запуска (можно удалить после завершения установки). Отмена после выхода из приложения означает, что его нужно снова открыть из меню Пуск. В режиме portable мастер может предложить установку в обычную папку; обновление рассчитано на установленную версию.

В текущем архиве источник пустой. Сетевой тест с реальным релизом, компиляция .NET и Inno Setup, оба сценария обновления и сохранение настроек проверяются на Windows; в среде подготовки они не выполнялись.
